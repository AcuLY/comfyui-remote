# Figma 页面设计与审核

## 已确认流程

用户要求每个页面先在 Figma 审核，再进入该页面正式前端实施。Figma 中的新稿默认“待审核”，不能由制作设计稿的 Agent 自行标为用户已批准。

| ID | 决策 |
| --- | --- |
| `FIG-01` | 页面先设计、用户审核、再实施；重大布局/交互变更重新提交对应页面审核。 |
| `FIG-02` | Figma 拥有页面视觉、布局、关键交互状态；仓库决策拥有业务规则、领域/API、迁移和技术栈。两者冲突时先按已确认业务规则修订设计。 |
| `FIG-03` | 首轮从系统主题、青绿/品红双模块外壳和图像生产任务页开始；不预先画完整套组件库或全部页面。 |
| `FIG-04` | 组件尽量对应 PrimeReact v10 现成能力；Figma 组件表明代码组件来源，复杂业务组合才自建。不得使用需要收费或许可申请的 UI Kit。 |
| `FIG-05` | 页面按实际需要覆盖加载、空态、失败、编辑中、只读、关键状态和桌面/移动布局；未涉及的状态不机械增加。 |
| `FIG-06` | 每个审核页记录 Figma 链接/节点、关联功能 ID、审核状态和反馈；实现后在浏览器对照验收，必要调整回写设计稿。 |
