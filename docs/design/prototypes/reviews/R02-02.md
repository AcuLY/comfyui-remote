# R02-02 项目上下文与导航恢复

## 开始依据与范围

用户于2026-09-12要求“基于整理的规则继续设计下一个原型”，本轮执行此前已登记的 `R02-02`，不新增子项。按既有顺序继续制作不追溯为 `R02-01` 全部设计已获批准；本项完成后单独交用户审核。

用户目的：从项目或任务来源进入项目，在项目内部切换视图，返回时保留原范围；刷新、浏览器前后和失效目标均有可预期的落点。

本项是已有导航外壳的扩展。首稿把项目与任务来源简化成了同一类项目记录，缺少图片与文件夹上下文，用户于2026-09-12指出功能和 UI/UX 理解偏差，并要求先对照旧前端与设计演示。随后明确：各类卡片应展示图片，能双列时优先双列，补上文件夹操作。本次在既有 `R02-02` 内登记并修正这些导航样本，不临时拆出任务号。

导航样本必须保留项目、小节／构图与独立任务之间的真实关系。全部修改只作用于原型的本地会话模拟数据，不调用业务写接口，也不修改真实项目、文件夹或图片。

2026-09-13用户授权“先处理已知的问题”。本轮依据2026-09-12对原型 `34912948` 的复盘，修复已呈现内容中的归档只读、资源关系、任务状态、来源恢复、目录范围、唯一身份、拖放／多选／排序及临界宽度问题，并同步共享主题、导航反馈和当前状态记录。以下契约先于修复更新；本轮浏览器实测、模型验证及源码核对现已逐项记录，旧验证不自动沿用，设计仍待用户审核。

生产项目单项／多选拖入文件夹、文件夹排序、生产小节单项／多选拖排及移入文件夹在本原型内补齐，键盘与触屏使用同一能力的“移动到”及上移／下移入口。该修复不等于 `R05-02`／`R05-05` 全任务及生命周期设计已获批准；文件夹删除、项目归档／删除流程、完整参数编辑、图片审核、素材编辑和生成／训练正式执行仍按各自任务推进。本轮不增加生产项目手工展示排序。

## 组件与应用职责

| 层次 | 实现选择 | 验证责任 |
| --- | --- | --- |
| 全局外壳 | 从 `R02-01` 提取同一可复用外壳；原独立页面继续可用 | 入口顺序、更多关闭规则、主题与侧栏收放不回退 |
| 项目层级 | 原生 `BreadCrumb`、带真实地址的返回链接 | 长项目名、小屏可读、层级返回与来源返回不同且明确 |
| 项目页签 | 原生 `TabMenu`，受控当前页签 | 生产四项与训练六项不混用；手机完整可达；键盘、地址及内容身份同步 |
| 来源样本与选择 | `PrimeReact` 公开 `Card`、`Checkbox`、输入、下拉与按钮，卡片外层承载应用导航 | 各资源图片及落点与对象身份一致；选择、主要导航和菜单命中区不冲突；双列下仍可读可操作 |
| 文件夹与移动菜单 | 生产范围内文件夹入口与路径面包屑，公开 `Menu`／`Dialog`／表单控件 | 单项和多选使用同一移动能力；归档只读、目标范围、取消及结果由应用统一校验；不侵入组件库内部样式 |
| 桌面拖放与排序 | 卡片和文件夹外层使用浏览器原生 `HTML` 拖放；上移／下移按钮及移动菜单是同一模型的替代入口 | 显示有效文件夹落点、同层前／后插入及携带数量；拒绝越界和只读写入，桌面拖放、键盘及触屏菜单结果一致 |
| 恢复逻辑 | 原型独立会话记录及浏览器历史 | 地址、筛选、文件夹范围、滚动与焦点交接由应用负责，不能只验证选中样式 |

已核对本工程 `PrimeReact 10.9.9` 的公开类型：`Tree` 的 `dragdropScope`／`onDragDrop` 面向树节点，`DataTable` 的 `reorderableRows`／`onRowReorder` 面向表格行，`OrderList` 的 `dragdrop`／`onChange` 面向自身列表重排。它们不能直接提供当前图片网格跨文件夹的多选拖放，因此本轮把范围、选择集合、落点和顺序放在应用层实现；保留原生组件的选择、菜单及对话框能力。此选择不认可暂停的 `R01-02` 为通用组织前置，也不把桌面原生拖放当作真机触控实现。

宽屏在外壳内容区呈现图片卡片与项目导航；手机顶部用于项目名称、返回、文件夹范围和当前页签，保留既有底栏。卡片按内容宽度优先双列，极窄屏退为单列；长名称允许换行，操作入口不能挤出卡片。训练六页签在小屏完整排列，不依赖只露出部分文字的横向滚动才能发现后续入口。
