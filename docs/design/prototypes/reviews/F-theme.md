# 基础原型统一主题方案与审核

## 当前目标与状态

用户要求“先调整一版”为真正统一的组件主题，并沿用“如非必要，不要对组件库做侵入式改动”的原则。**基础统一主题版已制作，待用户审核**；本轮主题、尺寸、交互及可用截图已记录，构建与文档检查已通过。已有检查不等同于用户确认，也不扩大为真机或全部状态组合已验收。

`8029fdfb` 对色相、浅色白底、字体、页面布局及短输入组合宽度的批准历史继续保留。新的主题生成方式、组件内部呈现、焦点与真实触控尺寸需本轮检查，不能直接沿用旧批准或 [InputNumber 修订记录](F-responsive.md)宣称通过。其余浅色中性色去色比较未采纳。

R01仍是暂停的列表稿，本轮不修改其设计或宣称全原型已经迁移。旧 `src/prototype.css` 暂供该稿使用，待后续R01迁移完成再删除。

## 统一主题的职责边界

下表职责已与入口、构建脚本及本轮实际加载链核对；具体浏览器检查和验证范围另列，不以职责说明替代验收。

| 层次 | 文件 | 本轮职责 |
| --- | --- | --- |
| 原始色值 | `src/tokens.css` | 唯一色值来源，保留两模块强调色、明暗表面和状态语义；不再手写另一份独立颜色表 |
| 主题映射 | `src/theme/theme-inputs.mjs` | 将语义变量映射到官方主题参数，定义标准／触控的尺寸与字体输入，不建立第二份独立色值 |
| 官方纯样式快照 | `src/theme/vendor/primereact-sass-theme/` | 固定官方提交的88份基础样式与浅／深各一份变量文件；保留来源记录及 `MIT` 许可，不包含包脚本或 `JavaScript` |
| 主题生成 | `scripts/build-theme.mjs` | 只读编译本地官方 `Sass` 快照，配合原始变量和参数映射生成四主题及标准／触控变体，不经 `npm` 安装官方 `Git` 主题包 |
| 生成主题 | `src/theme/primereact.css` | 承载组件内部结构、状态与焦点样式；由脚本生成，不用后续手写补丁逐控件修正内部细节 |
| 统一入口 | `src/prototype-provider.jsx` | 集中管理 `PrimeReactProvider` 行为、库语言配置、字体导入和主题入口；基础页先使用，R01 后续迁移 |
| 页面布局 | `src/prototype-layout.css` | 只负责原型页面布局和内容结构，不承担组件内部样式定制 |
| 基础页适配 | `src/foundations.css` | 保留基础页章节、色板、表单排列及视口布局，清理组件内部和透明热区覆盖 |
| 暂停的列表稿 | `src/prototype.css` | 暂供R01；基础新入口不再导入，不能据此称旧文件已删除或整个工程已迁移 |

基础页仍使用 `src/main.jsx` 的实际组件和本地模拟交互。输入、按钮等内部结构及焦点由官方主题生成，不在布局文件中模拟父容器焦点、移动隐藏输入或重排库内部按钮。

## 官方来源与版本边界

构建使用仓库内固定的官方纯 `Sass` 快照，来源为 [primefaces/primereact-sass-theme](https://github.com/primefaces/primereact-sass-theme/tree/0b17cdc8d1a5c89b2e7cf65b8431b85996385a41) 提交 `0b17cdc8d1a5c89b2e7cf65b8431b85996385a41`。已读取 `UPSTREAM.json`，记录上游版本 `10.8.5`、仓库、完整提交及90份源文件：`theme-base` 下88份 `.scss`，另有浅／深两份 `_variables.scss`；保留 `MIT` 许可，不复制包脚本或 `JavaScript`。详细维护说明由[主题来源说明](../src/theme/README.md)管理。

四份实际相关预设与 `PrimeReact 10.9.9` 的 `Git blob` 一致性依据保留，但不把快照称为完整的 `10.9.9` 精确源码。官方 `Git` 主题包已不再作为 `npm` 依赖安装；编译工具仅通过 `primereact-theme-sass=npm:sass@1.63.6` 锁定 `Dart Sass 1.63.6`，组件运行库仍为10.9.9。本次只调整来源存放和读取方式，主题参数、输出与已完成界面检查保持原范围，最终生成一致性及交付门禁另列。

运行组件库继续使用 `PrimeReact 10.9.9`，不因源码包标注变更组件库版本。`theme:build` 生成主题，`theme:check` 重新生成并比对现有产物；后者发现缺失或陈旧即失败，不重写文件。`dev` 先生成主题再启动，`build` 先检查主题新鲜度再构建。实现代理已报告 `theme:check` 通过，最终交付门禁仍由主代理复核。

统一提供器集中设置 `ripple: false`、中文库文案、描边输入风格和 `hideOverlaysOnDocumentScrolling: true`。v10 标签与实心按钮共用相关 `Sass` 颜色参数，因此 `Tag` 通过全局公开根插槽保留柔和状态背景和文字；`Toast` 也通过公开根插槽设置宽360px、最大为视口减32px。这两项是必要的根部颜色／宽度配置，不改写组件内部结构或事件，具体运行检查按下表范围判断。

## 本轮设计规则

| 编号 | 规则 | 实现和审核重点 |
| --- | --- | --- |
| FT-01 | 完整四主题 | 浅／深和生产／训练由同一官方来源与变量映射生成，覆盖普通、悬停、焦点、选中、禁用、错误及浮层 |
| FT-02 | 原生结构与焦点 | 使用组件公开属性和统一主题，撤去基础页按组件内部节点拼接出来的局部覆盖，不制造整圈焦点替身 |
| FT-03 | 真实触控尺寸 | 桌面表单标准高度 36px；触控表单以真实 44px 高度呈现，不以40px外观加透明区域冒充。复选框／单选／开关使用原生结构与可点击标签，不移动隐藏输入 |
| FT-04 | 清理覆盖职责 | 基础入口移除 `InputHitArea` 空标签、透明伪元素热区、隐藏输入偏移和强制内部高度／图标对齐等；页面布局文件只控制外层排列 |
| FT-05 | 保留设计方向 | 保留色相、浅色白底、字体组合、章节与色板布局及640px短输入组合上限；新主题呈现仍需用户审核 |
| FT-06 | 有界迁移 | 基础页先迁移；R01 暂用旧主题和布局混合文件，不在本轮扩展页面或宣布全原型统一完成 |

统一主题是本轮的新设计版本。官方生成的内部样式仍需验证可读性、焦点可见性、真实点击和错误反馈，不能用“来自官方”代替本产品的实际检查；确需额外覆盖时，先说明公开能力无法满足的产品或无障碍必要性。

主题上下文使用 `:where(:root[data-theme][data-module])`，只选择配色，不增加组件规则的优先级。已额外核对数字输入中间区域的原生直角及左右按钮的拼接圆角，防止主题作用域反过来压过库的结构规则。
