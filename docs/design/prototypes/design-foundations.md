# 新版前端基础设计规范

## 概述

1. **确认状态与适用范围。** 用户于 **2026-09-08** 确认了基础设计基线 **`8029fdfb`**，包括各视口适配、640px 同排组合上限和浅色纯白页面底色；其余浅色中性色去色比较未采纳。该确认历史保留。本轮按用户“如非必要，不要对组件库做侵入式改动”的要求，仅以 `InputNumber` 落实原生修订，已撤回人工整圈焦点与数字组件特殊内部覆盖，并记录指定尺寸、焦点和步进实测。其他已确认基础通用控件继续保留既有样式，不扩大重审范围，也不声明所有覆盖已清空。`R01-01` 仍暂停，相关改动未在本轮验证；记录见[适配审核记录](reviews/F-responsive.md)，现有生产样式仍由[根设计契约](../../../DESIGN.md)管理。
2. **设计方向：清晰可操作的创作工作台。** 柔和中性表面承托内容，绿色与玫瑰粉表达两个对等模块，独立状态语义解释结果；真实控件保持紧凑、清晰和可操作，再逐步组合业务页面。这是已确认基础的描述，不增加品牌命名或整页布局要求。基础展示页的目录、示例文案和模拟数据仅用于比较样式及交互，不成为业务需求。
3. **规则来源与验证边界。** 批准基线的变量与共享组件层来自 `src/tokens.css`、`src/prototype.css`；设备规则在 `src/foundations.css`，由基础入口的 `data-prototype="foundations"` 启用，`src/main.jsx` 提供章节导航、预览弹窗与交互样本。主题和模块偏好由 `src/use-prototype-preference.jsx` 维护，密度固定标准；恢复后的列表复用与调整另由 R01 记录。基础证据位于 `.impeccable/review/foundations-responsive/`，改前截图、整改后矩阵、控件宽度补充及真实验证限制均保留。用户确认不扩大已测范围，也不把旧列表检查提升为基础或生产验收。

## 色彩

1. **单一色值来源。** [tokens.css](src/tokens.css) 同时供页面实际样式及色样读数使用；本文与[扩展 sidecar](.impeccable/design.json)只描述角色，不维护第二份完整色值表。`canvas` 承托整页，`surface` 承载表单与面板，`surface-secondary` 区分工具栏和分组，`surface-hover` 表达悬停，`surface-floating` 用于顶部浮动表面。2026-09-08 按用户要求，浅色页面底色采用纯白；分区和控件继续以既有浅灰表面及边界区分。该调整只确认页面底色，其余浅色中性色的去色对照尚未采纳。
2. **模块与状态分开。** 2026-09-08 后续调整按用户提供的主题配置：图像生产采用 `accent #176E5A` 色相，训练采用用户明确选择的 `diffRemoved #A23F5D` 色相；明暗主题的各级颜色保留原有饱和度、明度与层级。这两个颜色是色相参考，不要求直接替换所有主题的强调色。`image` 为图像生产绿色，`training` 为 `LoRA` 训练玫瑰粉；`accent`、`accent-hover`、`accent-soft`、`on-accent` 随根元素 `data-module` 切换。柔和强调背景上的文字使用 `on-accent-soft`，浅色引用深一级的 `accent-hover`，深色引用 `accent`，满足正文对比度。成功、信息、警告和危险分别使用 `success`、`info`、`warning`、`danger` 及其柔和背景，保留文字或图标；配置中的 `diffRemoved` 在此仅提供训练色相，不改变应用危险语义。
3. **文字、边界与焦点分工。** 主要、次要和辅助文字分别使用 `text`、`text-secondary`、`text-muted`；分组线用 `border`，输入边界用 `border-control`。必要主题映射中，焦点色由 `focus` 引用当前模块的 `accent`，错误边界保持危险语义；焦点落点和复合组件的轮廓范围优先使用组件库原生行为，不为统一整圈轮廓模拟父容器焦点。深色页面、面板、文字、禁用状态及边框使用中性黑白灰。历史浅色辅助文字对页面底色和次级表面的对比分别为 4.96:1、4.73:1，仅覆盖当时两个组合。
4. **主题上下文在根元素。** 默认监听系统主题变化；手动选择明或暗后保存在原型专用 `cm-prototype-preference-v1`，直到点击“改为跟随系统”或选择“系统”。`data-theme` 与 `data-module` 在 `html` 上生效，因此挂到页面外层的下拉、对话框和 `Toast` 同样继承当前变量。模块选择保存到同一原型偏好记录；密度固定为标准，不作为可选择或持久化偏好。

## 字体与排版

1. **自托管字体。** 界面字体栈为 `'Geist Variable', 'Noto Sans SC Variable', sans-serif`：英文与数字优先 `Geist`，中文由 `Noto Sans SC` 承载；代码、路径和精确数值使用 `'IBM Plex Mono', monospace`，配合等宽数字。字体来自原型依赖，`IBM Plex Mono` 实际加载 `Latin 400`。
2. **实际字号与行高。** 常用角色如下，字阶已经确认；后续页面先复用角色，需要变化时按 `F-05` 提出调整。

| 编号 | 角色 | 字号 / 行高 | 字重与用途 |
| --- | --- | --- | --- |
| T-01 | 页面标题 | 32 / 44px | 600，页面标题与字阶样本 |
| T-02 | 主要分区 | 24 / 34px | 600，一级内容分区 |
| T-03 | 面板标题样本 | 20 / 28px | 600，字阶展示；对话框标题同为 20px |
| T-04 | 较长说明 | 16 / 24px | 正文字重，说明正文；实际小组件标题为 16px、600 |
| T-05 | 正文与控件 | 14 / 22px | 正文 400，按钮和字段标签常用 550 |
| T-06 | 辅助文字 | 12 / 18px | 辅助说明与元数据；局部说明按用途增加行高 |

3. **设备标题与字阶展示分开。** 字阶展示按标注尺寸呈现并保留用途标签。已确认的基础页应用为：宽屏页面标题 32／44px、分区标题 24／34px；768px 至不足 1200px 分别为 24／32px 与 20／28px；不足 768px 分别为 20／28px 与 18／26px。手机和粗指针的文本输入使用 16px 字体，常规正文保持 14px。后续组合先按相同设备角色复用，不能把展示刻度误作所有页面的实际标题。

## 布局

1. **间距以 4px 为基准。** 变量包含 4、8、12、16、20、24、32、40、48px；字段内常用 8px，按钮组用 12px，表单组与面板常用 24px。基准描述复用节奏，不要求图标间隙、描边或光学校正都必须是 4 的倍数。
2. **固定标准密度。** 精细指针桌面通用控件高 36px、行垂直内边距 12px，无密度选择器或旧密度偏好；不足 768px 或粗指针设备使用已确认的 40px 控件外观，不构成另一档可选密度。分段选择器的内层按钮为 36px。
3. **视觉尺寸与触摸范围分别设计。** 已确认的通用设备规则继续保留，优先通过组件公开能力、可见控件及外层布局满足。不得仅为像素对齐添加透明点击层或模拟焦点；确有产品或无障碍必要时，才做最小且能说明原因的覆盖并实际验证。本轮 `InputNumber` 恢复原生结构：手机实测根部与两按钮高 40px，根内边距为 0，根和按钮伪元素均不存在，不再附加透明点击热区，也不宣称它具有 44px 隐形目标。其他基础通用控件的已确认样式不因此整套重置。
4. **基础页响应式规则。** 1200px 及以上使用 184px 侧目录，工作区最大宽 1680px；不足 1200px 改为章节下拉和预览弹窗。色板与预览在不足 1024px 时上下排列；不足 768px 的色样使用小色块加文字、两列排列，字段单列；窄屏字段两列、宽屏三列。侧间距为宽屏 32px、窄屏 24px、手机 16px，不足 360px 时 12px；分区间距分别为 48／40／32px。宽度不足 1200px 且高度不超过 600px 时，顶部区域随内容滚动。连续区间媒体查询避免分数宽度断档；八个实测视口结果与所测限度见[适配审核记录](reviews/F-responsive.md)。

5. **控件组合有自己的宽度上限。** 名称、关键词等短文本输入与相邻操作组成一组时，按内容用途限制组合宽度，不能只依赖页面或分区的最大宽度。已确认的“同排控件”样本含内边距最大宽 640px，靠左排列；窄容器下占可用宽度，输入弹性收缩，按钮保持原尺寸与等高关系。该上限用于此类短输入组合；长文本编辑区、数据表等按内容另定，不统一套用。

## 层次与深度

1. **平面与浮层分工。** 常驻分区以中性表面和细边界区分；浮层阴影统一引用 `shadow-floating`，实际用于下拉、多选、对话框、`Toast` 及浮层样本。阴影色随明暗主题变化，不复制固定浅色阴影到新组件。
2. **透明只服务层次。** 顶栏使用 `surface-floating` 与 16px 背景模糊；对话框遮罩使用 `scrim`。对话框内容仍为不透明 `surface`，最大宽度受视口减 32px 限制。该样本不把透明面板推广为所有容器的默认外观。

## 形状

1. **小控件 8px，面板 12px。** 按钮、输入和下拉外壳用 `radius-control`；表单预览、状态容器和对话框用 `radius-panel`。标签、菜单项和复选框用 4px 小圆角；单选、开关与状态点保留各自原生圆形结构。
2. **标准密度下保持统一轮廓。** 桌面使用固定标准尺寸，手机的独立尺寸不改变既有圆角角色。分段选择器内项的 6px 圆角是组件内部配合关系，不增加为另一套面板基准。

## 组件

1. **组件来源与必要主题映射。** 使用 `PrimeReact` `10.9.9` `Styled`、`PrimeIcons` `7.0.0` 与 `React` `19.2.4`，保留已批准颜色、字体与通用标准密度的必要主题映射。主题样式放入组件库自己的 `primereact` 层，让库的内部结构规则优先；本轮只收敛 `InputNumber` 特殊覆盖，其他已确认组件不整套重置。交互由组件库负责，`sidecar` 静态摘录不能代替实际组件行为。

**非必要不侵入组件库。** 优先使用公开属性、主题配置和外层布局；不得只为像素对齐修改内部 `DOM`、重排内部按钮、模拟焦点或添加透明点击层。只有存在明确产品需求或无障碍必要性，公开能力仍不能满足时，才做最小、局部且可解释的覆盖，记录理由、范围及实际验证。该原则不把必要颜色／字体／通用密度映射一并撤销，也不自动扩展为本轮重做所有已确认组件。
2. **按钮与输入。** 已批准的主次操作、危险语义、常驻标签、说明、错误原因和只读／禁用区别保留。普通表单提交错误仍应能被发现和定位；不要把业务表单错误聚焦等同于为复合控件模拟整圈焦点。通用外层对齐不能成为重写组件内部结构的理由。

**本次数值输入修订。** `InputNumber` 通过公开 `buttonLayout="horizontal"` 使用原生横向步进，保留具名按钮和键盘能力。人工整圈伪元素焦点、数字按钮特殊宽度／布局／圆角／中性背景／图标缩放、数值强制居中、额外内边距热区及手动根点击聚焦均已撤去。焦点沿用 `Lara` 原生形状，只映射模块颜色：输入为 `0.2rem` 柔和阴影、无额外轮廓，复合根不模拟整圈焦点。人工方案已撤回，当前指定步进和设备实测见审核记录；本轮不声称所有既有样式覆盖已移除。
3. **选择与导航。** 使用 `Dropdown`、`MultiSelect`、`Checkbox`、`RadioButton`、`InputSwitch`、`SelectButton`、`TabView`。基础多选样本显示最多两个名称或数量摘要，在菜单内选择／取消，不保留小尺寸独立删除叉。宽屏侧目录与窄屏章节下拉对应同一内容，滚动到页底时末章正确高亮；窄屏预览打开主题／模块弹窗。本页导航只服务基础展示，不构成生产导航方案。
4. **反馈与浮层。** `Tag` 和 `Message` 保留状态文字及图标；`Skeleton` 对齐设备下的内容结构；空内容与失败样本提供创建或重试动作。预览设置与确认样本使用 `Dialog`，锁定背景滚动并在关闭后返回触发点；`Toast` 呈现轻量反馈。保存、确认与恢复只改变本地演示状态，没有业务接口含义；已测试的具体路径见本轮审核记录。
5. **动效与减少动画。** 色样轻移及按钮状态过渡使用 `160ms` 与 `cubic-bezier(0.16, 1, 0.3, 1)`。减少动态效果时，动画和过渡压至 `0.01ms`、动画只运行一次，关闭骨架移动和色样位移，滚动恢复为自动；源码中的未使用时长变量不作为新页面必须采用的规则。

## 应做与避免

1. 本轮 `InputNumber` 原生结构修订及指定实测已记录，`R01-01` 保持暂停且本轮未验证。保留 `8029fdfb` 基础批准历史和其他已明确规则；本次不扩大为整体基础重审，也不自动推进列表或业务页面。
2. 保留主次操作、可见标签、错误原因与恢复动作；浮层从根元素继承主题和模块，状态始终有可读文字或图标。
3. 不把基础已确认等同于后续页面已通过或生产已实现，不把本页目录、模拟内容或局部展示尺寸提升为业务需求；不从 `sidecar` 复制静态样本代替库组件行为。
4. 不把未使用变量、单次展示值或现有工具兼容提示编成设计基准。根 `PRODUCT.md` 的旧 `schema` 提示属于以后可选的 `Impeccable` `init` 适配，本次基础定稿不因此重写现有生产产品契约。
