# 新版前端基础设计规范

## 概述

1. **确认状态与适用范围。** `8029fdfb` 的基础批准历史保留，包括色相、字体、浅色纯白底色、页面布局和640px短输入组合上限；其余浅色中性色去色比较未采纳。基础统一主题的指定主题、尺寸和交互结果见[统一主题审核记录](reviews/F-theme.md)。用户于2026-09-09确认 [R01-01](reviews/R01.md) 的 `30fd53db` 版本并授权继续 [R01-02](reviews/R01-02.md)，确认仅覆盖列表子项，不扩大为全部主题状态或其他组合获批。现有生产样式仍由[根设计契约](../../../DESIGN.md)管理。
2. **设计方向：清晰可操作的创作工作台。** 柔和中性表面承托内容，绿色与玫瑰粉表达两个对等模块，独立状态语义解释结果；真实控件保持紧凑、清晰和可操作，再逐步组合业务页面。这是已确认基础的描述，不增加品牌命名或整页布局要求。基础展示页的目录、示例文案和模拟数据仅用于比较样式及交互，不成为业务需求。
3. **新主题职责与验证边界。** `src/tokens.css` 是唯一色值源，`src/theme/theme-inputs.mjs` 映射主题参数；`scripts/build-theme.mjs` 只读编译仓库内 `src/theme/vendor/primereact-sass-theme/` 的固定官方纯样式快照，生成 `src/theme/primereact.css`。提供器统一行为、语言、字体与主题入口；基础与列表共用 `prototype-layout.css`，各自视口布局在 `foundations.css` 和 `lists.css`。旧布局与组件补丁混合层随列表迁移删除；基础和列表分别记录实际验证，不扩大为正式前端已迁移。

## 色彩

1. **单一色值来源。** [tokens.css](src/tokens.css) 供页面变量、色样读数和本轮主题生成使用。生成CSS是派生产物，不另维护手写的第二份颜色表。`canvas` 承托整页，`surface`、`surface-secondary`、`surface-hover` 和 `surface-floating` 分别表达内容表面、分组、悬停与浮动表面。浅色页面底色纯白及现有色相保持；其余浅色中性色去色比较未采纳。新主题中各状态的可读性仍需实际检查。
2. **模块与状态分开。** 2026-09-08 后续调整按用户提供的主题配置：图像生产采用 `accent #176E5A` 色相，训练采用用户明确选择的 `diffRemoved #A23F5D` 色相；明暗主题的各级颜色保留原有饱和度、明度与层级。这两个颜色是色相参考，不要求直接替换所有主题的强调色。`image` 为图像生产绿色，`training` 为 `LoRA` 训练玫瑰粉；`accent`、`accent-hover`、`accent-soft`、`on-accent` 随根元素 `data-module` 切换。柔和强调背景上的文字使用 `on-accent-soft`，浅色引用深一级的 `accent-hover`，深色引用 `accent`，满足正文对比度。成功、信息、警告和危险分别使用 `success`、`info`、`warning`、`danger` 及其柔和背景，保留文字或图标；配置中的 `diffRemoved` 在此仅提供训练色相，不改变应用危险语义。
3. **文字、边界与焦点分工。** 主要、次要和辅助文字分别使用 `text`、`text-secondary`、`text-muted`；分组线用 `border`，输入边界用 `border-control`。必要主题映射中，焦点色由 `focus` 引用当前模块的 `accent`，错误边界保持危险语义；焦点落点和复合组件的轮廓范围优先使用组件库原生行为，不为统一整圈轮廓模拟父容器焦点。深色页面、面板、文字、禁用状态及边框使用中性黑白灰。历史浅色辅助文字对页面底色和次级表面的对比分别为 4.96:1、4.73:1，仅覆盖当时两个组合。
4. **主题上下文在根元素。** 默认监听系统主题变化；手动选择明或暗后保存在原型专用 `cm-prototype-preference-v1`，直到点击“改为跟随系统”或选择“系统”。`data-theme` 与 `data-module` 在 `html` 上生效，因此挂到页面外层的下拉、对话框和 `Toast` 同样继承当前变量。模块选择保存到同一原型偏好记录；密度固定为标准，不作为可选择或持久化偏好。

## 字体与排版

1. **自托管字体。** 字体方案保持：界面使用 `'Geist Variable', 'Noto Sans SC Variable', sans-serif`，代码、路径和精确数值使用 `'IBM Plex Mono', monospace`。字体依赖导入已集中到 `src/prototype-provider.jsx`，与主题入口共用；实际检查范围见本轮记录。
2. **实际字号与行高。** 常用角色如下，字阶已经确认；后续页面先复用角色，需要变化时按 `F-05` 提出调整。

| 编号 | 角色 | 字号 / 行高 | 字重与用途 |
| --- | --- | --- | --- |
| T-01 | 页面标题 | 32 / 44px | 600，页面标题与字阶样本 |
| T-02 | 主要分区 | 24 / 34px | 600，一级内容分区 |
| T-03 | 面板标题样本 | 20 / 28px | 600，字阶展示；对话框标题同为 20px |
| T-04 | 较长说明 | 16 / 24px | 正文字重，说明正文；实际小组件标题为 16px、600 |
| T-05 | 正文与控件 | 14 / 22px | 正文 400，按钮和字段标签常用 550 |
| T-06 | 辅助文字 | 12 / 18px | 辅助说明与元数据；局部说明按用途增加行高 |

3. **设备标题与字阶展示分开。** 页面标题和字阶展示继续沿用既有布局：宽屏页面标题 32／44px、分区标题 24／34px，窄屏24／32px与20／28px，手机20／28px与18／26px。字阶展示保留标注尺寸和用途。组件内部字号由统一主题参数生成，不在布局文件中逐控件强制覆盖；新主题的实际表单字号和可读性待同轮验证。

## 布局

1. **间距以 4px 为基准。** 变量包含 4、8、12、16、20、24、32、40、48px；字段内常用 8px，按钮组用 12px，表单组与面板常用 24px。基准描述复用节奏，不要求图标间隙、描边或光学校正都必须是 4 的倍数。
2. **标准密度与真实触控尺寸。** 按用户本轮确认，统一主题使用桌面36px、手机／粗指针普通控件40px高度；可编辑输入保留16px字号，纯图标按钮、关闭与分页动作保留真实44px。尺寸通过官方主题参数生成，不添加透明热区或内部标签高度补丁。数值输入等复合组件保留库原生按钮布局，整体高度按其组合实测，不强制所有复合控件等高40px。密度不是用户可切换或持久化设置；此前44px表单验证保留为历史，本轮调整与实际验证见[R01审核记录](reviews/R01.md)。
3. **使用真实控件与公开能力。** 基础新版移除 `InputHitArea` 空标签、透明伪元素点击层、隐藏输入偏移以及强制内部高度／图标对齐等做法。复选框、单选框、开关使用组件原生结构与可点击标签；外层布局负责排列，不修改内部命中关系。确需额外覆盖时，须有明确产品或无障碍理由，优先公开能力，并记录最小范围及实测。
4. **基础页响应式规则。** 1200px 及以上使用 184px 侧目录，工作区最大宽 1680px；不足 1200px 改为章节下拉和预览弹窗。色板与预览在不足 1024px 时上下排列；不足 768px 的色样使用小色块加文字、两列排列，字段单列；窄屏字段两列、宽屏三列。侧间距为宽屏 32px、窄屏 24px、手机 16px，不足 360px 时 12px；分区间距分别为 48／40／32px。宽度不足 1200px 且高度不超过 600px 时，顶部区域随内容滚动。连续区间媒体查询避免分数宽度断档；八个实测视口结果与所测限度见[适配审核记录](reviews/F-responsive.md)。

5. **控件组合有自己的宽度上限。** 名称、关键词等短文本输入与相邻操作组成一组时，按内容用途限制组合宽度，不能只依赖页面或分区的最大宽度。已确认的“同排控件”样本含内边距最大宽 640px，靠左排列；窄容器下占可用宽度，输入弹性收缩，按钮保持原尺寸与等高关系。该上限用于此类短输入组合；长文本编辑区、数据表等按内容另定，不统一套用。

## 层次与深度

1. **平面与浮层分工。** 页面常驻分区保留既有表面和层次。组件下拉、多选、对话框及轻提示的深度样式由统一主题生成，页面样本使用既有语义变量；不在布局层为每个浮层追加独立阴影补丁，实际新主题表现待审核。
2. **透明只服务层次。** 顶栏使用 `surface-floating` 与 16px 背景模糊；对话框遮罩使用 `scrim`。对话框内容仍为不透明 `surface`，最大宽度受视口减 32px 限制。该样本不把透明面板推广为所有容器的默认外观。

## 形状

1. **圆角角色与主题分工。** 既有控件8px、页面面板12px的形状方向保留。组件内部的圆角拼接和单选／开关结构交给官方主题，通过公开主题参数表达，不再逐内部节点覆盖；新生成结果仍需审核。
2. **页面布局不重写内部轮廓。** 页面容器负责组合宽度、留白和排列，不能以统一边缘为由重排组件内部按钮、覆盖图标尺寸或模拟父容器焦点。

## 组件

1. **组件来源与完整主题生成。** 运行库保持 `PrimeReact 10.9.9`。官方纯 `Sass` 快照固定提交 `0b17cdc8d1a5c89b2e7cf65b8431b85996385a41`，上游标注版本 `10.8.5`；88份基础样式及浅／深变量文件连同来源清单、`MIT` 许可保留在仓库，不安装官方 `Git` 主题包，也不复制其脚本或 `JavaScript`。四相关预设的 `Git blob` 一致性仅作兼容依据，不称完整 `10.9.9` 精确源码。编译器保持 `Dart Sass 1.63.6`。四主题参数与输出不因来源存放改变，`Tag` 仍仅通过公开根槽位保留柔和语义色；实际检查与最终门禁见 F-theme。

**非必要不侵入组件库。** 优先公开属性、统一主题配置和外层布局；不得只为像素对齐修改内部 `DOM`、重排按钮、模拟焦点或添加透明点击层。确有产品或无障碍必要且公开能力不足时，才做最小、局部且可解释的覆盖并记录验证。基础和列表均采用完整主题，后续原型继续复用同一入口，按组合验证实际表现。
2. **按钮与输入。** 已批准的主次操作、危险语义、常驻标签、说明、错误原因和只读／禁用区别保留。普通表单提交错误仍应能被发现和定位；不要把业务表单错误聚焦等同于为复合控件模拟整圈焦点。通用外层对齐不能成为重写组件内部结构的理由。

**数值输入遵循同一主题。** `InputNumber` 通过公开 `buttonLayout="horizontal"` 使用横向步进，保留具名按钮和键盘能力；不再为它单独添加焦点形状或内部布局补丁。此前人工整圈焦点已撤回，局部原生修订属于历史证据；当前生成主题下的数值尺寸、焦点和步进须重新实测。
3. **选择与导航。** 使用 `Dropdown`、`MultiSelect`、`Checkbox`、`RadioButton`、`InputSwitch`、`SelectButton`、`TabView`。基础多选样本显示最多两个名称或数量摘要，在菜单内选择／取消，不保留小尺寸独立删除叉。宽屏侧目录与窄屏章节下拉对应同一内容，滚动到页底时末章正确高亮；窄屏预览打开主题／模块弹窗。本页导航只服务基础展示，不构成生产导航方案。
4. **反馈与浮层。** 状态文字、图标、创建／重试动作和本地模拟反馈保留。浮层滚动、语言配置和行为统一由 `src/prototype-provider.jsx` 管理；章节下拉用公开 `appendTo="self"`，文档滚动关闭浮层，不手写定位补偿。`Toast` 通过公开根槽位配置360px宽及视口减32px上限，不改内部结构。本轮已测指定菜单滚动、手机／短横屏设置、确认弹窗焦点返回和错误反馈，范围见记录。
5. **动效与减少动画。** 页面色样动效与组件主题动效分开管理，组件使用官方主题能力。本轮新主题的四个骨架伪元素在减少动态效果下已测时长 `1e-05s`、迭代1次；不把旧版动画名称或未测控件直接列为本轮结果。

## 应做与避免

1. `R01-01` 已由用户确认，当前按授权进入 `R01-02`，使用基础统一主题并保留色相、白底、字体和页面布局方向。新的组件与组合呈现须独立审核，不以基础或列表批准宣称其他组合或业务页面通过。
2. 保留主次操作、可见标签、错误原因与恢复动作；浮层从根元素继承主题和模块，状态始终有可读文字或图标。
3. 不把基础已确认等同于后续页面已通过或生产已实现，不把本页目录、模拟内容或局部展示尺寸提升为业务需求；不从 `sidecar` 复制静态样本代替库组件行为。
4. 不把未使用变量、单次展示值或现有工具兼容提示编成设计基准。根 `PRODUCT.md` 的旧 `schema` 提示属于以后可选的 `Impeccable` `init` 适配，本次基础定稿不因此重写现有生产产品契约。
