# HTML 原型基础设计记录

## 概述

1. **适用范围：仅 `docs/design/prototypes/`。** 本文从已构建的基础审核样本提取复用规则，供后续扩展原型。`status: current` 表示记录当前有效；所有具体色值、字体、尺寸及控件呈现仍为待用户审核候选，不改变[根设计契约](../../../DESIGN.md)。审核编号沿用[基础设计清单](foundations/README.md)的 F-01～F-14。
2. **候选方向：清晰可操作的创作工作台。** 柔和中性表面承托内容，青绿与粉色表达两个对等模块，独立状态语义解释结果；用真实控件比较选择，再组合业务页面。这是基础样本的描述，不增加未经确认的品牌命名或整页布局要求。
3. **记录来源：源码与已有验收。** 本轮已完成独立收尾审查及一次整改复核；1440px 桌面、390px 手机截图与测量记录位于仓库本地 `.impeccable/review/`。`checks.json` 记录主题跟随、手动覆盖与持久化、保存加载及成功、下拉、表单校验、状态重试和 `Escape` 关闭对话框；`fix-metrics.json` 与 `contrast.json` 记录触摸和浅色辅助文字整改。它们说明已覆盖的原型行为，不替代用户设计确认或生产验收。

## 色彩

1. **单一色值来源。** [tokens.css](src/tokens.css) 同时供页面实际样式及色样读数使用；本文与[扩展 sidecar](.impeccable/design.json)只描述角色，不维护第二份完整色值表。`canvas` 承托整页，`surface` 承载表单与面板，`surface-secondary` 区分工具栏和分组，`surface-hover` 表达悬停，`surface-floating` 用于顶部浮动表面。
2. **模块与状态分开。** `image` 为图像生产青绿，`training` 为 `LoRA` 训练品红至粉色；`accent`、`accent-hover`、`accent-soft`、`on-accent` 随根元素 `data-module` 切换。成功、信息、警告和危险分别使用 `success`、`info`、`warning`、`danger` 及其柔和背景，保留文字或图标；暂停样本使用警告语义。
3. **文字、边界与焦点分工。** 主要、次要和辅助文字分别使用 `text`、`text-secondary`、`text-muted`；分组线用 `border`，输入边界用 `border-control`，焦点用独立 `focus`。整改记录中的浅色辅助文字对页面底色为 4.96:1、对次级表面为 4.73:1；该结论仅覆盖这两个组合。
4. **主题上下文在根元素。** 默认监听系统主题变化；手动选择明或暗后保存在原型专用 `cm-prototype-preference-v1`，直到点击“改为跟随系统”或选择“系统”。`data-theme` 与 `data-module` 在 `html` 上生效，因此挂到页面外层的下拉、对话框和 `Toast` 同样继承当前变量。模块和密度选择也保存到同一原型偏好记录。

## 字体与排版

1. **自托管字体。** 界面字体栈为 `'Geist Variable', 'Noto Sans SC Variable', sans-serif`：英文与数字优先 `Geist`，中文由 `Noto Sans SC` 承载；代码、路径和精确数值使用 `'IBM Plex Mono', monospace`，配合等宽数字。字体来自原型依赖，`IBM Plex Mono` 实际加载 `Latin 400`。
2. **实际字号与行高。** 常用角色如下；字阶为原型候选，后续页面先复用角色，再提出必要调整。

| 编号 | 角色 | 字号 / 行高 | 字重与用途 |
| --- | --- | --- | --- |
| T-01 | 页面标题 | 32 / 44px | 600，页面标题与字阶样本 |
| T-02 | 主要分区 | 24 / 34px | 600，一级内容分区 |
| T-03 | 面板标题样本 | 20 / 28px | 600，字阶展示；对话框标题同为 20px |
| T-04 | 较长说明 | 16 / 24px | 正文字重，说明正文；实际小组件标题为 16px、600 |
| T-05 | 正文与控件 | 14 / 22px | 正文 400，按钮和字段标签常用 550 |
| T-06 | 辅助文字 | 12 / 18px | 辅助说明与元数据；局部说明按用途增加行高 |

3. **窄屏调整作用于真实标题。** 640px 及以下，页面 `h1` 改为 24 / 36px，分区 `h2` 改为 20px；字阶展示仍保留 32px 样本，方便比较。不要把展示刻度误认为手机页面的实际标题尺寸。标题字重为 600，页面标题字距为 `-0.025em`。

## 布局与密度

1. **间距以 4px 为基准。** 变量包含 4、8、12、16、20、24、32、40、48px；字段内常用 8px，按钮组用 12px，表单组与面板常用 24px。基准描述复用节奏，不要求图标间隙、描边或光学校正都必须是 4 的倍数。
2. **桌面密度只调尺寸。** 紧凑、标准、舒展分别使用 32、36、44px 控件高度，行垂直内边距分别为 8、12、16px；正文字号保持不变。分段选择器有自己的内层高度，不能将桌面通用控件高度断言套用于每个子部件。
3. **触摸优先保障。** 640px 及以下或粗指针设备将通用控件高度提升为 44px，紧凑密度也不例外；分段按钮同步提升。数值步进器使用水平按钮，移动整改实测增减按钮均为 44 × 44px，所有分段选项高为 44px。手机导航、文字操作和可点击标签保持至少 44px 高；视觉较小的选择框通过标签与输入热区扩展触摸面积。
4. **本页响应式组成。** 桌面为 220px 目录与内容列，整体最大宽 1800px；1200px 及以下压缩目录与色板，900px 及以下目录变为横向换行、色板与表单分开，640px 及以下表单和规格样本改为单列。已有 1440px 与 390px 记录中，页面滚动宽度等于视口宽度；中间断点的规则来自源码，不表示每个宽度都经过浏览器验证。

## 层次与景深

1. **平面与浮层分工。** 常驻分区以中性表面和细边界区分；浮层阴影统一引用 `shadow-floating`，实际用于下拉、多选、对话框、`Toast` 及浮层样本。阴影色随明暗主题变化，不复制固定浅色阴影到新组件。
2. **透明只服务层次。** 顶栏使用 `surface-floating` 与 16px 背景模糊；对话框遮罩使用 `scrim`。对话框内容仍为不透明 `surface`，最大宽度受视口减 32px 限制。该样本不把透明面板推广为所有容器的默认外观。

## 形状与圆角

1. **小控件 8px，面板 12px。** 按钮、输入和下拉外壳用 `radius-control`；表单预览、状态容器和对话框用 `radius-panel`。标签、菜单项和复选框用 4px 小圆角；单选、开关与状态点保留各自原生圆形结构。
2. **密度不改变轮廓。** 切换密度只改控件高度与行间距，不同时改字号和圆角。分段选择器内项的 6px 圆角是组件内部配合关系，不增加为另一套面板基准。

## 组件

1. **组件来源与主题层。** 实际使用 `PrimeReact` `10.9.9` `Styled`、`PrimeIcons` `7.0.0` 与 `React` `19.2.4`；先加载 `Lara Light Teal` 基础主题，再加载 `tokens.css` 和 `prototype.css` 统一覆盖公开组件类。交互由库组件负责，`PrimeReactProvider` 关闭 `ripple`；`sidecar` 只保存少量静态外观摘录，不能代替 `React` 组件的键盘、状态和浮层行为。
2. **按钮与输入。** 主按钮用模块强调色，次按钮用表面与控件边界，文字按钮用强调色，危险操作用危险语义。输入保留常驻标签、辅助说明、错误原因、只读与禁用区别；焦点为 2px 描边、3px 偏移。数值输入通过具名水平增减按钮操作。
3. **选择与导航。** 使用 `Dropdown`、`MultiSelect`、`Checkbox`、`RadioButton`、`InputSwitch`、`SelectButton`、`TabView`；色彩和密度切换不可取消当前选项。目录是锚点导航，移动端换行显示；它是基础样本的目录，不是已确认的生产导航方案。
4. **反馈与浮层。** `Tag` 和 `Message` 保留状态文字及图标；`Skeleton` 对齐内容结构；空内容与失败样本提供创建或重试动作。`Dialog` 负责确认样本，`Toast` 负责轻量结果反馈；保存、确认和重试只修改本地演示状态，没有业务接口含义。
5. **动效与减少动画。** 色样轻移及按钮状态过渡使用 `160ms` 与 `cubic-bezier(0.16, 1, 0.3, 1)`。减少动态效果时，动画和过渡压至 `0.01ms`、动画只运行一次，关闭骨架移动和色样位移，滚动恢复为自动；源码中的未使用时长变量不作为新页面必须采用的规则。

## 复用与限制

1. 后续原型先复用当前语义变量、字体角色、触摸规则与 `PrimeReact` 控件；变更候选时同步实际样本和本记录，按 F-01～F-14 提交用户审核。
2. 保留主次操作、可见标签、错误原因与恢复动作；浮层从根元素继承主题和模块，状态始终有可读文字或图标。
3. 不把独立收尾审查通过等同于用户确认，不把本页目录、模拟内容或局部展示尺寸提升为生产规范；不从 `sidecar` 复制静态样本代替库组件行为。
4. 不把未使用变量、单次展示值或现有工具兼容提示编成设计基准。根 `PRODUCT.md` 的旧 `schema` 提示属于以后可选的 `Impeccable` `init` 适配，本轮不因此修改生产产品契约。
